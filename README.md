# Лабораторна робота №2 — Gazebo та ArduPilot SITL

У проєкті підготовлено ROS 2-пакет `fpv_lab2` з двома польотними вузлами. Gazebo запускається зі штатним світом `maze.sdf` з пакета ArduPilot. Додаткові перешкоди не додаються. Для варіанта 19 ціль задається від фактичної стартової позиції: `x_target = x0 + 8,2 м`, `y_target = y0 − 0,4 м`.

## Завдання 1. Підготовка середовища

Dockerfile збирає середовище ROS 2 Humble, Gazebo Harmonic, ArduPilot SITL і потрібні ROS-пакети. Docker Compose налаштовує WSL D3D12 GPU та доступні WSL 12 логічних процесорів. Перший запуск або перебудова образу:

```bash
docker compose build ardupilot_ros
```

## Завдання 2. Автоматизація запуску

З кореня проєкту запусти:

```bash
./start_sim.sh
```

Скрипт запускає контейнер, збирає `fpv_lab2` і запускає штатний світ ArduPilot Maze з дроном та 2D LiDAR. Залиш цей термінал відкритим. Для зупинки натисни `Ctrl+C`, потім виконай:

```bash
docker compose down
```
Після редагування коду повторно запусти `./start_sim.sh`: пакет зберігається в `fpv_labs` і автоматично збирається.

Після запуску `./start_sim.sh` Gazebo, SITL і ROS 2 залишаються в контейнері. У звичайному терміналі Ubuntu/WSL команду `ros2` напряму вводити не потрібно: користуйся обгорткою `./ros2.sh`, яка виконує її в контейнері з налаштованим середовищем ROS 2.

Перевір, що ROS 2 вузли симуляції запущені:

```bash
./ros2.sh node list
```

У списку мають бути `/ap_v1` та `/ros_gz_bridge`. Для перегляду тем ROS 2:

```bash
./ros2.sh topic list
```

## Завдання 3. Початковий приклад

В іншому терміналі з кореня проєкту запусти вузол і дочекайся повідомлення про завершену посадку:

```bash
./ros2.sh run fpv_lab2 flight_test
```

Вузол перевіряє pre-arm, переходить у GUIDED, озброює двигуни, злітає на 2 м, зависає 30 секунд, переходить у LAND і завершується після приземлення.

## Завдання 4. Політ до точки варіанта 19

Після завершення завдання 3 запусти:

```bash
./ros2.sh run fpv_lab2 custom_flight
```

Вузол зчитує стартову позицію, виконує зліт на 2 м і летить прямою до `x0 + 8,2 м`, `y0 − 0,4 м`. Ця пряма в штатному світі Maze не перетинає стіни відповідно до методички. Після досягнення цілі вузол утримує позицію, сідає та завершується.

## Завдання 5. Перевірка результату

`custom_flight` виводить стартові координати, ціль, фактичну позицію перед посадкою та горизонтальну похибку. Перевір, що у виводі є повідомлення про досягнення цілі й завершення посадки. Для окремого запису журналів замість звичайного запуску використовуй:

```bash
./ros2.sh run fpv_lab2 flight_test 2>&1 | tee flight_test.log
./ros2.sh run fpv_lab2 custom_flight 2>&1 | tee custom_flight.log
```

Похибка цілі: `e = sqrt((x_actual − x_target)^2 + (y_actual − y_target)^2)`. У коді фініш фіксується при горизонтальній похибці не більш як 0,20 м та відхиленні висоти не більш як 0,25 м.

## Склад пакета

- `flight_test` — контрольний зліт, зависання й посадка.
- `custom_flight` — політ до індивідуальної точки варіанта 19 і автоматична посадка.
- `flight_common.py` — спільна взаємодія з сервісами ArduPilot і контроль етапів польоту.
- `start_sim.sh` — запуск середовища та збірка ROS-пакета.
- `ros2.sh` — запуск команд ROS 2 з системного термінала всередині контейнера.
- `docker-compose.yml` і `Dockerfile` — конфігурація контейнера та залежностей.

Після перезапуску код та конфігурація залишаються у файлах проєкту. Gazebo завантажує штатний лабіринт під час кожного запуску світу.
